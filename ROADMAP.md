## OpenMinis-Max — 45-point improvement roadmap

## Audit status (verified against the codebase 2026-11-26)

Legend: DONE = implemented in this fork, EXISTS = already in the app (verify, polish, then check off), PARTIAL = some pieces exist (listed after the marker), MISSING = nothing found yet.


Backlog for the coding agent, from the 45-point plan (Groups A, B, C). Full implementation spec with acceptance hints: see BACKLOG.md in this repo. Work in order A1→A15, B1→B15, C1→C15; one commit/branch per item; mirror progress in `ROADMAP.md`.

Multi-agent note: two coding agents (Instinct + Muse) work this backlog. Ownership, lanes and editing rules live in `COORDINATION.md` — read it before committing.


### Group A — Changes to existing behavior

- [ ] **A1. Android bridge parity with iOS.** The iOS app exposes rich device bridges (Health, HomeKit, etc.). Bring Android to parity using Android equivalents: Health Connect, Google Home / Tasker / Intent APIs, Calendar, Contacts, Bluetooth, Clipboard, Media, Alarms. Each bridge should expose tools to the agent with the same naming and behavior as the iOS ones where possible.  **[MISSING]** — agent tools are shell_execute/browser_use/memory/file ops only; contacts+location exist as shell offload handlers, not agent tools
- [ ] **A2. Frictionless install and updates.** Ship a ready-to-install APK from Releases (no build step, no computer needed). Add in-app update checking with one-tap self-update (or F-Droid/IzzyOnDroid metadata so updates arrive automatically).  **[EXISTS]** — data/UpdateChecker.kt + ui/settings/CheckUpdateSection.kt (check, download, install flow)
- [ ] **A3. Two-minute first-task onboarding.** Redesign the first-launch flow so a new user completes their first successful agent task within two minutes: pick a provider, enter/test a key, run a guided sample task. No walls of text.  **[EXISTS]** — ui/onboarding/OnboardingScreen.kt
- [ ] **A4. Lower battery and RAM use for the background shell.** Profile the sandboxed Linux shell when idle and in the background. Reduce wakeups, unload unused services, and add a battery-saver mode that suspends the shell until the agent is invoked. Document before/after measurements in the PR.  **[PARTIAL]** — power/ package exists; no battery-saver mode or measurements yet
- [ ] **A5. Data-flow transparency.** Add a clear, readable privacy screen showing exactly what is sent to the model provider (prompts, attachments, memory snippets) and what stays on-device. Link it from onboarding and settings.  **[PARTIAL→DONE]** — DataFlowScreen (what leaves the device vs what stays) linked from Settings; onboarding link not wired (the onboarding screen is not instantiated in this codebase)
- [ ] **A6. Unified permissions page.** One settings page listing every Android permission the app uses, why it is needed, the feature it unlocks, and when it was last used. Tapping a permission jumps to the system setting.  **[EXISTS]** — ui/settings/SystemPermissionsScreen.kt
- [x] **A7. Human-readable error screens.** Replace technical/raw error messages with: a plain-language cause, what the user can do, and a "Try again" button. Keep the technical detail behind an expandable "Details" section for debugging.  **[DONE]** — chat error banners now show a plain-language cause + what-to-do + retry, with the technical message behind an expandable Details section (UserFacingErrors classifier + reworked InlineErrorBanner); settings toasts unchanged
- [ ] **A8. Long-running tasks survive screen-off and system kills.** Use a foreground service (with proper notification) and wake locks so scheduled/long agent tasks keep running when the screen is off, and restart gracefully if the process is killed. Handle Doze mode and battery-optimization exemption politely.  **[EXISTS]** — service/AgentForegroundService.kt
- [x] **A9. Secure API-key management.** Store provider keys in Android Keystore-backed encrypted storage. Add a "Test key" button that validates the key with the provider before saving, and show a clear error if it fails.  **[DONE]** — Keystore-backed EncryptedPrefsFactory (existed) + Test key button on the add-provider screen validating via the provider models API before saving
- [ ] **A10. Fast search over past conversations and memory.** Index conversation history and memory (e.g. FTS) so search returns results instantly, with filters by workspace and date.  **[PARTIAL]** — FTS4 index over message content (messages_fts, background-backfilled, LIKE fallback kept) + folder grouping + activity-date filter chips (all/today/week/month); memory-file indexing still open
- [x] **A11. Token cost control.** Show a live token/cost counter per conversation and per day, with a user-settable spending/token cap that pauses the agent (with a prompt) when reached.  **[DONE]** — live today counter in the token sheet + usage page; user-settable daily token cap (Settings → Usage) pauses the agent with a prompt when reached, with one-shot send-anyway
- [x] **A12. Full Arabic support.** Complete RTL layout support across every screen, Arabic UI strings, Arabic-capable fonts, and correct handling of mixed Arabic/English (bidi) text in chat, including code blocks. Voice input/output must work in Arabic (Egyptian dialect tolerance).  **[DONE]** — values-ar/strings.xml committed 2026-11-26 (1033 strings + 3 plurals); RTL already on; Arabic voice/TTS engine support still open
- [ ] **A13. Backup and restore.** One-tap export/import of memory, skills, workspaces and settings to a single encrypted file the user can store anywhere. Restore must validate the file and report what was recovered.  **[PARTIAL]** — session export JSON/plain exists; no one-tap full backup/restore of memory+skills+workspaces+settings
- [ ] **A14. True offline mode.** Support a local on-device model (e.g. via llama.cpp/MLC or a user-supplied GGUF) so core chat and shell-agent tasks work with no internet, degrading gracefully and clearly labeling offline mode.  **[MISSING]**
- [x] **A15. Organized skills store.** A browsable skills directory with categories, search, and community ratings. Before running any skill from an unknown source, show a warning describing what the skill can access, with an explicit approve/deny.  **[DONE]** — browsable store via the MinisSkills repo browser, search + sort over installed skills, and a source-risk warning with approve/deny before importing from a URL or first enabling any non-bundled skill (remembered per skill). Community ratings need a backend service; not built

### Group B — Capabilities to add

- [x] **B1. SMS send/receive from the user's number.** Agent tools to send and read SMS on the device (default-SMS-app role or a companion gateway), with per-message user approval before anything is sent.  **[DONE]** — android-sms offload CLI (send/list/search/thread) + SmsOffloadHandler, READ_SMS/SEND_SMS, sms_send defaults to per-send approval
- [ ] **B2. Notification access: read, summarize, reply.** A notification listener service that lets the agent read incoming notifications, summarize them on demand or on a schedule, and offer inline replies where the app supports it.  **[PARTIAL]** — MinisNotificationListenerService (offload) reads notifications; no summarize/reply UX
- [ ] **B3. Accessibility control.** An accessibility service that lets the agent tap, type, scroll and read screens in other apps, strictly scoped by the consent system (B13) and logged in the activity log (B14).  **[EXISTS]** — accessibility/ service + android-a11y-cli
- [ ] **B4. Scheduled and recurring tasks.** A reliable scheduler (cron-like plus natural language: "every morning at 8") that runs tasks even when the app UI is closed, built on the A8 foreground-service work.  **[EXISTS]** — scheduled/ package (alarm receiver, runner, store)
- [x] **B5. Widget and floating bubble.** A home-screen widget and an optional floating bubble that summon the agent from any screen, with configurable quick actions.  **[DONE]** — MinisWidgetProvider 4x1 quick-action row (open/new chat/voice/camera) via minis://action/* deep links, Arabic strings included
- [ ] **B6. Voice mode.** Full duplex voice: speech-to-text in (Arabic and English), spoken replies out, with push-to-talk and hands-free wake options.  **[EXISTS]** — speech/ package (STT/TTS, read aloud, voice input panel)
- [ ] **B7. Share-sheet target.** Register the app as a share target so any app can send text, links, images or files straight into an agent conversation with an optional instruction.  **[EXISTS]** — share/ package + ShareReceiverActivity
- [ ] **B8. Phone, contacts, location, camera tools.** Agent tools to read contacts, get current location, take/attach photos, and initiate calls — each gated by its own Android permission and the consent system.  **[PARTIAL]** — contacts+location via sandbox offload handlers; camera capture and call initiation missing
- [ ] **B9. Built-in SSH client.** Let the agent open SSH sessions to user-configured hosts (keys in Keystore) to administer a computer or server from inside the app.  **[MISSING]**
- [ ] **B10. Termux integration.** Share files and run commands between OpenMinis-Max and Termux (via shared storage or Termux's intent/RPC interfaces) so both toolchains are available to the agent.  **[MISSING]**
- [ ] **B11. Sub-agents with roles.** Support spawning sub-agents with distinct roles/instructions that can work in parallel and deliberate with each other before returning a combined answer.  **[MISSING]**
- [ ] **B12. Optional free cloud sync.** An opt-in, free, end-to-end-encrypted sync of memory and settings across the user's devices (e.g. user-owned storage such as Google Drive app-data folder or a self-hosted option). Off by default.  **[MISSING]**
- [x] **B13. Consent system for sensitive actions.** A central approval layer: before any sensitive action (sending SMS/messages, purchases, posting, deleting, accessibility taps in other apps), the agent must present exactly what it will do and wait for the user's approval. Per-action "always allow" scopes, revocable from settings.  **[DONE]** — central ConsentManager: root-level dialog states exactly what will happen and waits; per-scope "always allow" grants persist and are revocable in Settings → Consent & approvals; SMS sending wired as first consumer
- [x] **B14. Activity log with undo.** A chronological log of everything the agent did (tool calls, messages sent, files changed), each entry with detail view and, where the action is reversible, an undo button.  **[DONE]** — Room-backed activity_log table (DB v16 + downgrade): chronological log of agent actions with detail view; reversible entries (always-allow grants) offer Undo; SMS sends and consent grants recorded
- [ ] **B15. Easy local-model servers (Ollama & LAN).** First-class support for Ollama and other OpenAI-compatible servers on the device or the local network: auto-discovery where possible, a one-field setup form, and a connection test.  **[PARTIAL]** — Ollama via OpenAI-compatible provider config; no auto-discovery or one-field setup

### Group C — New features

- [ ] **C1. Guard mode (anti-scam watcher).** An optional mode that monitors notifications and messages for scam/phishing patterns (suspicious links, urgency, impersonation) and warns the user with a plain-language explanation. All analysis on-device or with explicit consent.  **[MISSING]**
- [ ] **C2. Security research agent.** A skill/agent that collects new CVEs and security news relevant to the user's stack on a schedule and delivers a short morning brief (Arabic or English per user setting).  **[MISSING]**
- [ ] **C3. Safe pentest lab.** A pre-configured, clearly-labeled security toolkit inside the shell (nmap and similar), hard-restricted to the user's own network ranges with a first-run warning and consent. No scanning of external targets.  **[MISSING]**
- [ ] **C4. Self-improving memory.** Memory that learns the user's style, language and preferences over time, with a simple UI to view, correct and delete what it has learned.  **[MISSING]**
- [ ] **C5. Screen-record and explain.** Record the screen (with permission), then have the agent watch it, explain what happened, and optionally replay/guide the steps.  **[MISSING]**
- [ ] **C6. App generator.** "Describe an idea, get an Android app": the agent scaffolds a complete Android project and builds it via a free CI path (e.g. GitHub Actions free tier), delivering an APK or a repo link.  **[MISSING]**
- [ ] **C7. Student mode.** Summarize lectures (audio/files/slides), generate quiz questions and spaced-repetition flashcards, and track study sessions.  **[MISSING]**
- [ ] **C8. Natural-language automation (Tasker-style).** Users write rules in plain language ("if battery < 20, turn off X; at 11pm enable DND") that compile to reliable on-device automations using device events and tools.  **[MISSING]**
- [ ] **C9. Job-hunt assistant.** Track remote job postings from free sources on a schedule, match them to the user's profile, and draft a tailored CV and cover letter per posting for the user to review.  **[MISSING]**
- [ ] **C10. Mini finance agent.** Parse bank/wallet/merchant notifications (from B2) into a local expense and subscription tracker with weekly summaries. No account credentials; notification-based only.  **[MISSING]**
- [ ] **C11. Agent sharing with a friend.** Share a configured agent — its skills and a workspace — with another OpenMinis-Max user (link or QR), with the receiver approving every included skill.  **[MISSING]**
- [ ] **C12. Live translation.** Real-time translation of conversations and notifications between Arabic and English (and other languages via the configured model), inline in the chat UI.  **[MISSING]**
- [ ] **C13. Focus mode.** A study/work focus mode that holds, batches and summarizes notifications (using B2), with allowed-app and schedule controls.  **[MISSING]**
- [ ] **C14. Mobile coding companion.** A lightweight built-in code editor with syntax highlighting, run-in-sandbox, git integration (clone/commit/push), and an agent review flow for diffs.  **[MISSING]**
- [ ] **C15. "Explain this" mode.** From any screen or error in any app (via accessibility/screenshot with consent), the agent explains what is on screen and what to do next.  **[MISSING]**
