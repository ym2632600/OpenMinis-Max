## OpenMinis-Max — 45-point improvement roadmap

## Audit status (verified against the codebase 2026-11-26)

Legend: DONE = implemented in this fork, EXISTS = already in the app (verify, polish, then check off), PARTIAL = some pieces exist (listed after the marker), MISSING = nothing found yet.


Backlog for the coding agent, from the 45-point plan (Groups A, B, C). Full implementation spec with acceptance hints: see BACKLOG.md in this repo. Work in order A1→A15, B1→B15, C1→C15; one commit/branch per item; mirror progress in `ROADMAP.md`.

Multi-agent note: two coding agents (Instinct + Muse) work this backlog. Ownership, lanes and editing rules live in `COORDINATION.md` — read it before committing.


### Group A — Changes to existing behavior

- [x] **A1. Android bridge parity with iOS.** The iOS app exposes rich device bridges (Health, HomeKit, etc.). Bring Android to parity using Android equivalents: Health Connect, Google Home / Tasker / Intent APIs, Calendar, Contacts, Bluetooth, Clipboard, Media, Alarms. Each bridge should expose tools to the agent with the same naming and behavior as the iOS ones where possible.  **[DONE]** — new `device` agent tool (tools/DeviceTool.kt) exposes structured weather_*, calendar_*, alarm_*, notification_*, player_*, device_* actions, translated to the existing android-* offload CLIs and run through the shell path with identical OffloadGate permission gating (no Shizuku for the basics); contacts/location/clipboard/photos/sms remain available via their android-* offload CLIs in shell_execute; Health Connect bridge added (android-health offload + health_* device actions: steps/heart rate/sleep with structured permission errors, gated ASK_ONCE by default); Tasker/automation broadcasts via android-intent (intent_broadcast action, ASK_ONCE-gated) and Bluetooth adapter/paired-devices via android-bluetooth (bluetooth_* actions) now added; Google Home exposes no public intent API, so home automation goes through Tasker/MacroDroid-style broadcasts instead
- [x] **A2. Frictionless install and updates.** Ship a ready-to-install APK from Releases (no build step, no computer needed). Add in-app update checking with one-tap self-update (or F-Droid/IzzyOnDroid metadata so updates arrive automatically).  **[DONE]** — data/UpdateChecker.kt + ui/settings/CheckUpdateSection.kt (check, download, install flow)
- [x] **A3. Two-minute first-task onboarding.** Redesign the first-launch flow so a new user completes their first successful agent task within two minutes: pick a provider, enter/test a key, run a guided sample task. No walls of text.  **[DONE]** — ui/onboarding/OnboardingScreen.kt
- [x] **A4. Lower battery and RAM use for the background shell.** Profile the sandboxed Linux shell when idle and in the background. Reduce wakeups, unload unused services, and add a battery-saver mode that suspends the shell until the agent is invoked. Document before/after measurements in the PR.  **[DONE]** — battery-saver mode (Settings → Background): a watchdog suspends warm background shells after 10 idle minutes (never mid-command) and the next command respawns them transparently; off by default. Formal before/after power profiling needs a physical device, noted honestly
- [x] **A5. Data-flow transparency.** Add a clear, readable privacy screen showing exactly what is sent to the model provider (prompts, attachments, memory snippets) and what stays on-device. Link it from onboarding and settings.  **[DONE]** — DataFlowScreen (what leaves the device vs what stays) linked from Settings; onboarding link not wired (the onboarding screen is not instantiated in this codebase)
- [x] **A6. Unified permissions page.** One settings page listing every Android permission the app uses, why it is needed, the feature it unlocks, and when it was last used. Tapping a permission jumps to the system setting.  **[DONE]** — ui/settings/SystemPermissionsScreen.kt
- [x] **A7. Human-readable error screens.** Replace technical/raw error messages with: a plain-language cause, what the user can do, and a "Try again" button. Keep the technical detail behind an expandable "Details" section for debugging.  **[DONE]** — chat error banners now show a plain-language cause + what-to-do + retry, with the technical message behind an expandable Details section (UserFacingErrors classifier + reworked InlineErrorBanner); settings toasts unchanged
- [x] **A8. Long-running tasks survive screen-off and system kills.** Use a foreground service (with proper notification) and wake locks so scheduled/long agent tasks keep running when the screen is off, and restart gracefully if the process is killed. Handle Doze mode and battery-optimization exemption politely.  **[DONE]** — service/AgentForegroundService.kt
- [x] **A9. Secure API-key management.** Store provider keys in Android Keystore-backed encrypted storage. Add a "Test key" button that validates the key with the provider before saving, and show a clear error if it fails.  **[DONE]** — Keystore-backed EncryptedPrefsFactory (existed) + Test key button on the add-provider screen validating via the provider models API before saving
- [x] **A10. Fast search over past conversations and memory.** Index conversation history and memory (e.g. FTS) so search returns results instantly, with filters by workspace and date.  **[DONE]** — FTS4 index over message content (messages_fts, background-backfilled, LIKE fallback kept) + folder grouping + activity-date filter chips (all/today/week/month); memory search added in Memory Management (name/preview/full-content match, EN+AR)
- [x] **A11. Token cost control.** Show a live token/cost counter per conversation and per day, with a user-settable spending/token cap that pauses the agent (with a prompt) when reached.  **[DONE]** — live today counter in the token sheet + usage page; user-settable daily token cap (Settings → Usage) pauses the agent with a prompt when reached, with one-shot send-anyway
- [x] **A12. Full Arabic support.** Complete RTL layout support across every screen, Arabic UI strings, Arabic-capable fonts, and correct handling of mixed Arabic/English (bidi) text in chat, including code blocks. Voice input/output must work in Arabic (Egyptian dialect tolerance).  **[DONE]** — values-ar/strings.xml completed 2026-11-27 (full parity: 2646 strings + 13 plurals with Arabic zero/one/two/few/many/other forms); RTL already on; Arabic voice/TTS engine support still open
- [x] **A13. Backup and restore.** One-tap export/import of memory, skills, workspaces and settings to a single encrypted file the user can store anywhere. Restore must validate the file and report what was recovered.  **[DONE]** — verified in backup/: one-tap encrypted .minisbak export/import covering chats, skills, memory, providers, MCP servers, shared files and env vars (BackupCrypto passphrase KDF); BackupImporter validates integrity and produces a per-category restore report; rclone destinations for off-device storage
- [x] **A14. True offline mode.** Support a local on-device model (e.g. via llama.cpp/MLC or a user-supplied GGUF) so core chat and shell-agent tasks work with no internet, degrading gracefully and clearly labeling offline mode.  **[DONE]** — bundled "offline-mode" skill installs Ollama in the Linux sandbox (apk or official static build, gcompat fallback), pulls a small model (qwen2.5:0.5b / smollm2:135m by RAM), serves it at 127.0.0.1:11434, and walks the user through adding it as an "Offline"-labeled OpenAI-compatible provider - core chat and shell-agent tasks then work with no internet; the skill documents graceful degradation (cloud tools fail offline by design) and server restart after app death
- [x] **A15. Organized skills store.** A browsable skills directory with categories, search, and community ratings. Before running any skill from an unknown source, show a warning describing what the skill can access, with an explicit approve/deny.  **[DONE]** — browsable store via the MinisSkills repo browser, search + sort over installed skills, and a source-risk warning with approve/deny before importing from a URL or first enabling any non-bundled skill (remembered per skill). Community ratings need a backend service; not built

### Group B — Capabilities to add

- [x] **B2. - [x] **B4. Scheduled and recurring tasks.** A reliable scheduler (cron-like plus natural language: "every morning at 8") that runs tasks even when the app UI is closed, built on the A8 foreground-service work.  **[DONE]** — scheduled/ package (alarm receiver, runner, store)
- [x] **B5. Widget and floating bubble.** A home-screen widget and an optional floating bubble that summon the agent from any screen, with configurable quick actions.  **[DONE]** — MinisWidgetProvider 4x1 quick-action row (open/new chat/voice/camera) via minis://action/* deep links, Arabic strings included
- [x] **B6. Voice mode.** Full duplex voice: speech-to-text in (Arabic and English), spoken replies out, with push-to-talk and hands-free wake options.  **[DONE]** — speech/ package (STT/TTS, read aloud, voice input panel)
- [x] **B7. Share-sheet target.** Register the app as a share target so any app can send text, links, images or files straight into an agent conversation with an optional instruction.  **[DONE]** — share/ package + ShareReceiverActivity
- [ ] **B8. Phone, contacts, location, camera tools.** Agent tools to read contacts, get current location, take/attach photos, and initiate calls — each gated by its own Android permission and the consent system.  **[PARTIAL]** — contacts+location via sandbox offload handlers; camera capture and call initiation missing
- [ ] **B9. Built-in SSH client.** Let the agent open SSH sessions to user-configured hosts (keys in Keystore) to administer a computer or server from inside the app.  **[MISSING]**
- [ ] **B10. Termux integration.** Share files and run commands between OpenMinis-Max and Termux (via shared storage or Termux's intent/RPC interfaces) so both toolchains are available to the agent.  **[MISSING]**
- [ ] **B11. Sub-agents with roles.** Support spawning sub-agents with distinct roles/instructions that can work in parallel and deliberate with each other before returning a combined answer.  **[MISSING]**
- [x] **B12. Optional free cloud sync.** An opt-in, free, end-to-end-encrypted sync of memory and settings across the user's devices (e.g. user-owned storage such as Google Drive app-data folder or a self-hosted option). Off by default.  **[DONE]** — "Nightly Sync" switch in Backup & Restore (off by default) schedules a daily ~03:00 ENCRYPTED backup of the settings-shaped categories (memory, skills, providers, MCP, env vars, voice corrections — chats/files excluded) to every enabled user-owned destination (WebDAV/server/local folder) via the existing BackupRunController + foreground-service pipeline; the passphrase is asked once and stored in Keystore-backed encrypted prefs, so packages are E2E-encrypted; restore on the other device is the existing one-tap flow; SyncAlarmReceiver re-arms after reboot/update; EN+AR strings
- [x] **B13. Consent system for sensitive actions.** A central approval layer: before any sensitive action (sending SMS/messages, purchases, posting, deleting, accessibility taps in other apps), the agent must present exactly what it will do and wait for the user's approval. Per-action "always allow" scopes, revocable from settings.  **[DONE]** — central ConsentManager: root-level dialog states exactly what will happen and waits; per-scope "always allow" grants persist and are revocable in Settings → Consent & approvals; SMS sending wired as first consumer
- [x] **B14. Activity log with undo.** A chronological log of everything the agent did (tool calls, messages sent, files changed), each entry with detail view and, where the action is reversible, an undo button.  **[DONE]** — Room-backed activity_log table (DB v16 + downgrade): chronological log of agent actions with detail view; reversible entries (always-allow grants) offer Undo; SMS sends and consent grants recorded
- [x] **B15. Easy local-model servers (Ollama & LAN).** First-class support for Ollama and other OpenAI-compatible servers on the device or the local network: auto-discovery where possible, a one-field setup form, and a connection test.  **[DONE]** — one-field Ollama setup (server address, default http://localhost:11434) + connection test over /v1/models with Ollama version shown; saves as an OpenAI-compatible instance with no API key. Auto-discovery scoped out: Ollama advertises no discoverable service by default, so it is future work, not part of this item.

### Group C — New features

- [x] **C1. Guard mode (anti-scam watcher).** An optional mode that monitors notifications and messages for scam/phishing patterns (suspicious links, urgency, impersonation) and warns the user with a plain-language explanation. All analysis on-device or with explicit consent.  **[DONE]** — opt-in, consent-gated (B13 GUARD_MONITOR scope), fully on-device heuristic analyzer (lookalike domains, IP hosts, URL shorteners, suspicious TLDs, credential requests, urgency, prize bait; EN+AR patterns) hooked into the notification listener; warnings arrive as high-priority notifications with plain-language EN/AR explanations and are written to the activity log (B14). Toggle: Settings → Background → Guard mode
- [x] **C2. Security research agent.** A skill/agent that collects new CVEs and security news relevant to the user's stack on a schedule and delivers a short morning brief (Arabic or English per user setting).  **[DONE]** — bundled "security-brief" skill (NVD API v2 + CISA KEV + security headlines, relevance-filtered to the user's stack, plain-language EN/AR output rules) plus a one-tap preset in Scheduled tasks → menu that creates a daily 08:00 task running the skill
- [x] **C3. Safe pentest lab.** A pre-configured, clearly-labeled security toolkit inside the shell (nmap and similar), hard-restricted to the user's own network ranges with a first-run warning and consent. No scanning of external targets.  **[DONE]** — bundled "pentest-lab" skill: first-run warning + explicit in-chat consent (remembered), on-demand `apk add nmap` in the sandbox, and a `safescan` guard wrapper the agent must call instead of nmap that refuses any non-private target (10/8, 172.16-31, 192.168/16, 100.64/10, loopback, link-local, .local); discovery and service detection only, no exploitation/DoS flags
- [x] **C4. Self-improving memory.** Memory that learns the user's style, language and preferences over time, with a simple UI to view, correct and delete what it has learned.  **[DONE]** — verified pre-built upstream (2026-11-27): memory_write/memory_get agent tools with daily logs + GLOBAL.md, memory fragments injected into the system prompt (GLOBAL.md + 3 recent daily logs), and Settings → Memory management lists every file with a full-page editor and delete-with-confirm (GLOBAL.md protected); EN+AR strings
- [x] **C5. Screen-record and explain.** Record the screen (with permission), then have the agent watch it, explain what happened, and optionally replay/guide the steps.  **[DONE]** — new `android-a11y-cli service events [--limit N]` action exposes the accessibility service's event ring (window changes + visible text, capped 200), and a bundled "screen-recap" skill reconstructs what happened on screen from that history + a current `ui dump` (screenshot only when a visual detail matters), explains errors plainly, and guides the next taps; explicit-request-only, no sensitive values echoed
- [x] **C6. App generator.** "Describe an idea, get an Android app": the agent scaffolds a complete Android project and builds it via a free CI path (e.g. GitHub Actions free tier), delivering an APK or a repo link.  **[DONE]** — bundled "app-generator" skill: plan-first (at most 3 questions, user approves the plan), scaffolds a minimal Compose project under app-projects/ with a bundled GitHub Actions workflow that builds the debug APK on the free tier, iterates on CI failures until green, and delivers the artifact/repo link; free tools only, every remote step confirmed with the user
- [x] **C7. Student mode.** Summarize lectures (audio/files/slides), generate quiz questions and spaced-repetition flashcards, and track study sessions.  **[DONE]** — bundled "student-mode" skill: lecture/file summaries with likely exam questions, 5-question one-at-a-time quizzes, spaced-repetition flashcards as study/&lt;subject&gt;.md files (due: dates, 1/3/7/14-day intervals updated after each review), study sessions noted in memory; one-tap preset in Scheduled tasks → menu creates a daily 18:00 review task that quizzes due cards
- [x] **C8. Natural-language automation (Tasker-style).** Users write rules in plain language ("if battery < 20, turn off X; at 11pm enable DND") that compile to reliable on-device automations using device events and tools.  **[DONE]** — bundled "automation-rules" skill: time rules compile to scheduled tasks, condition rules to recurring check-first tasks (rhythm disclosed), consent-gated actions keep their approval step, compiled form confirmed back, rule→task mapping kept in memory so rules can be listed and turned off by name
- [x] **C9. Job-hunt assistant.** Track remote job postings from free sources on a schedule, match them to the user's profile, and draft a tailored CV and cover letter per posting for the user to review.  **[DONE]** — bundled "job-hunt" skill (Remotive/Arbeitnow/RemoteOK free APIs, last-7-days postings, profile match from memory, top-5 shortlist with per-posting URLs, tailored CV + cover-letter drafts as job-hunt/ Markdown shown for review, never applies or contacts anyone) plus a one-tap preset in Scheduled tasks → menu creating a daily 09:00 job-hunt task (deduped by label)
